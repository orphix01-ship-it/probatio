Every certificate and every run, successful or not, is appended here. Each entry stores the SHA-256 hash of the entry before it, so changing, deleting or reordering any past entry breaks the chain from that point on.

How it works

Propose, certify, record

UntrustedPropose

Exhaustive search, annealing, or an AI model suggests candidates. Nothing it says is believed.

ContainedSandbox

AI-written programs run without network, process spawning or file access outside a scratch folder.

TrustedCertify

A small exact checker recomputes every claim from the raw candidate.

Tamper-evidentRecord

Certificates are stored by content hash in a hash-chained ledger.

Why. AI systems can now generate mathematical candidates far faster than people can. The results that hold up, such as AI agents settling open Erdős problems in Lean, all rest on a checker that confirms each one independently. PROBATIO is an open implementation of that loop.

Trust levels. T1 means a proof assistant kernel decided (Lean). T2 means exact integer or GF(2) computation by open, tested code. Floating-point simulation is never enough on its own.

Two implementations. The Python checkers produce certificates. This page re-checks them with a separate JavaScript implementation of the same method. The two are tested against each other on every stored certificate.

Optimal in family. When an exhaustive search covers a whole symmetry-reduced family, the best result is optimal within that family. That claim comes from open search code, is labelled separately from the certificate, and its symmetry reduction is tested against brute force.

Limits. Experimental and unaudited. Verification proves correctness, not novelty. The current results are calibration: known optima rediscovered from scratch. A result that beats the recorded best is marked CANDIDATE-NEW and is claimed only after a human literature review.
